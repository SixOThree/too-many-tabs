Too Many Tabs now has a one-page website. It opens on the title card, and one click anywhere plays the video fullscreen with sound.

The page, its poster frame and a new render.py web command are committed on feature/too-many-tabs-video as e9037fc. The 245 MB video file is gitignored and isn't on any host yet. Choosing that host is the one open decision, and the Hosting section covers it.

What the page does

The video itself opens on a blue VCR screen that reads PLAY ▶, so the stopped page borrows that look. The title card sits under a blue fade rising from the bottom, with a large PLAY ▶ in the same on-screen-display lettering. The whole screen is the button.

Clicking it makes the page fullscreen and starts playback with sound. Browsers only allow either of those after a click or a key press, which is why the page can't start by itself when it loads.

While the video plays, nothing sits on top of it, and the cursor hides after 2.5 seconds without mouse movement. At the end the video holds on its closing card with PLAY underneath, and PLAY starts it again from the beginning. If the MP4 can't load, a blue screen replaces PLAY and says the video didn't load and to reload the page.

iPhone Safari can't make a page element fullscreen, so on iPhone the page hands the video to Safari's own fullscreen player. That code hasn't run on a real iPhone yet.

Hosting

Where the site will live

Open decision

The site is three static files. Any host has to do two things.

  • Accept a 245 MB file. GitHub rejects files over 100 MB, which rules out GitHub Pages unless the video lives somewhere else.
  • Answer HTTP range requests. Without them the browser can't skip ahead in the video.

The options, none of them started:

  • Put all three files on a host that accepts the 245 MB video.
  • Serve the page from anywhere, GitHub Pages included, and point the video's src in index.html at storage that takes large files.
  • Make a smaller encode to fit under a host's limit. The VHS noise will show compression artifacts sooner than clean footage would.

Rebuild and preview

render.py web reads out\too_many_tabs_1080p.mp4, so render and mux the 1080p master first.

.\.venv\Scripts\python.exe render.py web     # site\too_many_tabs.mp4 and site\poster.jpg
npx http-server site -p 8765 -c-1            # then open http://127.0.0.1:8765/

Preview with a server that supports range requests. npx http-server does. Python's built-in http.server ignores them, so skipping ahead may not work there.
